## 一、使用说明与勾选口径

1. **本表只认可复现的证据。** 每一项都写明「怎么判」与「期望值」；勾选前必须真的跑过或看过对应产物，
   **不接受「应该没问题」**——本项目已多次证明：`assert path.exists()` 这类只查存在性的判据，
   会让真实缺陷活过好几个阶段（`[FIX-FEED-LATEST-01]` 就是这么活过 D6→D12 的）。
2. **三类证据必须在结论旁标明级别**，不得混用：

   | 级别 | 含义 | 例子 |
   | --- | --- | --- |
   | **机器证据** | 脚本可重跑、结果可复算 | `pytest --junitxml` 的三计数、`verify_feed.py`、`verify_demo_pack.py` |
   | **实机证据** | 在真实环境做过的动作与留档 | 断网/杀进程续跑、浏览器截图 |
   | **人证** | 真人听测或人工判断 | MOS「都没问题」、演示录屏 |

   ⚠️ **MOS 只有人证，没有评分表也没有均分。** 本表中凡涉及 MOS 的行，
   只写「真人听测确认达标」，**禁止在答辩材料里改写成「MOS 均分 X」**。
3. **勾选符号**：`[x]` 已自测通过　`[ ]` 未自测/待做　`[~]` 部分达成（必须紧跟说明）。
4. **自测顺序**：先 `A`（起得来）→ `B/C/D`（功能与指标）→ `E`（文档）→ `F/G`（留档与演示物）。
   只要 `A` 不过，后面全部无意义。

## 十、K 组：本阶段发现并已修复的缺陷（D14 新增）

> 单独立组，是因为这四条**都不是「顺手改改」**：它们各自代表一类「机器判据看不见」的盲区，
> 且全部活过了此前所有阶段的回归。**它们能被发现，靠的是「真的去用一遍」而不是「再跑一次测试」。**

| 编号 | 缺陷 | 症状 | 为什么此前所有测试都没发现 | 修法与复验 |
| --- | --- | --- | --- | --- |
| K1 | **`/feed` 前端页面路由被 vite 代理吞掉** | 直接访问或按 F5 打开「频道设置」页 → 收到后端的 `{"detail":"Not Found"}`，页面打不开（点导航链接进去却正常） | 所有页面级用例都走客户端路由跳转，**没有任何一条用例以 URL 直开该页**；接口用例只关心 `/api` 与 `/feed/<token>.xml` | 代理键由前缀 `'/feed'` 收紧为正则 `'^/feed/.+$'`。复验：`/feed` 返回 SPA HTML、`/feed/<token>.xml` 仍返回 RSS，两条同时成立；浏览器留证该页 6/6 通过 |
| K2 | **演示账号 `local` 登不进 Web** | `password_hash` 是 1 字节占位串 `x`，`bcrypt.checkpw` 抛 `ValueError` 被 `verify_password` 吞成「口令错误」——**能建任务、能出成片，却登不进 Web**；全新环境重建库后必然复现 | 此前全部验证走 CLI 与 HTTP API，**没有任何一条用例真的用浏览器登录过它**；且「哈希损坏」与「口令打错」在接口层返回完全一样（401），症状无法区分 | 新增 `scripts/ensure_demo_account.py`：写入 `bcrypt` 12 轮哈希后**立刻双向回验**（正确口令 True / 错误口令 False），并支持 `--if-unset`；`make_episode.py` 的占位值由 `"x"` 改为空串（空串被显式判为失败，比「看似哈希实则非法」更诚实）。复验：直连 8000 与经代理 5173 各得 200 + HttpOnly Cookie，错误口令 401 |
| K3 | **成片页「脚本回看」是死代码** | DONE 状态的成片页只有播放器与下载按钮，`TaskDetail.tsx` 里写好的脚本回看区块永不渲染 | 脚本只在 `SCRIPT_READY` 状态拉取，而区块渲染在 `status === 'DONE'` 分支下——**两个条件互斥**；组件测试只覆盖了可编辑态 | 拉取条件放宽为 `SCRIPT_READY` 或 `DONE`（**只读**，编辑卡仍只对 `SCRIPT_READY` 开放）。复验：浏览器留证该页正文由 124 字增至 1120 字，截图可见逐行 A/B 对话稿；前端门禁 4/4 全过 |
| K4 | **`backend/assets/README.md` 三类漂移** | ① 时长标注过期（11.60/9.90 应为 6.54/7.46）；② **版本沿革表整体错位一代**；③ 内部自相矛盾（`INTRO_SPEED` 1.05 vs `--speed-intro` 1.10；把**未采用**的修复方向「把 `zero_shot_spk_id` 改为空串」写成事实） | README 不在交付文档集内，**不参与 `check_spec_docs.py` 门禁**；且它的内容不参与任何测试 | 逐目录 `ffprobe` 实测重建版本沿革表（并写明「目录里装的是被替换下来的旧素材」这一读表口径）、时长表改为实测值、把「修复方向」改写为**已实施且落地在何处**、标注 `INTRO_TONE` 为有意忽略的死配置。复验：表内每一行时长均可由 `ffprobe` 复算 |

> **不计入已完成功能的加分**。特别是 K2：它说明「跑过 CLI 就算验证过」这种论证方式不可靠。
