## 二、D2 —— 模型 A/B 定稿

### 2.1 实验设计

**单变量**：同一批 3 句文本、同一音色档案、同一环境（`COSYVOICE_ONNX_DEVICE=cpu`、fp16、单并发），仅切换模型版本。

```
python scripts/smoke_tts.py --model both
```

| 常驻 allocated | **2442 MB** | 3310 MB | **+868 MB (+35.5%)** |
| 常驻 reserved | 2642 MB | 3496 MB | +854 MB |

### 2.3 定稿结论

**主模型 = CosyVoice2-0.5B。**

1. **显存量级差异是决定性的。** CosyVoice3 的 `flow.pt` 为 1329 MB（CV2 为 430 MB）、`speech_tokenizer_v3.onnx` 为 925 MB（v2 为 473 MB）。在净可用 4.32 GB 的硬约束下，其**常驻量就已接近 reserved 门槛**，峰值双口径均超限，系统级只剩 1.47 GB——与桌面程序（壁纸引擎、浏览器、Overlay）争抢时必然 OOM。
2. **速度优势不足以构成选型理由。** CV3 单句快 14.7%，但折算到 1000 字端到端仅约 25 s，而代价是 +825 MB 峰值显存。
3. **CosyVoice3 记入 V2.0 候选**，触发条件为「换用 8 GB+ 显存设备」。`tts.py` 仅需改 `COSYVOICE_MODEL_DIR` 即可切换，无需改代码。

### 2.4 过程中发现的上游接口差异（重要）

**首次 A/B 时 CosyVoice3 直接失败**，且错误信息具有误导性：

```
AssertionError: <|endofprompt|> not detected in CosyVoice3 text or prompt_text, check your input!
  at cosyvoice/llm/llm.py:479   assert 151646 in text
```

同时主线程报出**看似无关**的错误：

```
RuntimeError: Calculated padded input size per channel: (3). Kernel size: (4).
  at cosyvoice/hifigan/f0_predictor.py:97
```

**根因与假象的区分**：`assert` 在 LLM 生成线程内抛出 → 生成流中断 → `token2wav` 只拿到 3 帧 mel → `hift.f0_predictor` 的因果卷积核（size 4）大于输入长度（3）而报错。**声码器的报错是级联结果，不是根因。**

**真实原因**：CosyVoice3 的 `prompt_text` 语义与 CosyVoice2 不同。

| 模型 | `prompt_text` 形式 |
| --- | --- |
| CosyVoice2 | prompt 音频的**纯转写文本**（无前缀、无结束符） |
| CosyVoice3 | 固定提示语 **+** 转写文本 **+** 提示结束符，三段拼接（精确形式见下方代码块；上游 `example.py:76`、`runtime/triton_trtllm/infer_cosyvoice3.py:175` 均如此） |

CosyVoice3 的精确前缀（字符串字面量，末尾为特殊结束符）：

```text
You are a helpful assistant.<|endofprompt|>
```

另有一条**只在用 `zero_shot_spk_id` 时才会暴露**的细节：`frontend_zero_shot` 在该参数非空时用 `{**self.spk2info[zero_shot_spk_id]}` 覆盖 `model_input`，**传入的 `prompt_text` 参数不参与编码**（只用于上游的「synthesis text too short」告警判定）。因此正确做法是：

- **注册**（`add_zero_shot_spk`）时用**带前缀**版本 —— 保证 spk2info 内的 `prompt_text_token` 含 151646；
- **推理**（`inference_zero_shot`）时传**纯转写文本** —— 避免 `len(i) < 0.5 * len(prompt_text)` 的误告警刷屏。

已在 `api/services/tts.py` 的 `VoiceProfile.registered_prompt_text()` / `inference_prompt_text()` 中实现该适配。

## 三、D2 —— 音色建档

### 3.1 已建档案

| id | 名称 | 性别 | 素材 | 时长 | prompt_text |
| --- | --- | --- | --- | --- | --- |
| `voice_a` | 女声·知性沉稳 | female | `backend/voices/voice_a.wav`（16 kHz 单声道） | **3.48 s** ⚠️ | 希望你以后能够做的比我还好呦。 |

建档工具：`scripts/make_voice_profile.py`，支持：

```bash
# 已知转写文本（推荐）
python scripts/make_voice_profile.py --id voice_b --name "男声·沉稳" \
    --wav D:/my_voice.m4a --text "大家好，我是本期节目的另一位主播。" --gender male

# 无转写文本时用 whisper 自动识别
python scripts/make_voice_profile.py --id voice_b --wav D:/my_voice.wav --asr

# 只做格式体检
python scripts/make_voice_profile.py --wav D:/my_voice.wav --check
```

工具会把任意输入统一为 **16 kHz 单声道**，并按计划书 4.4 节 S6 的 **5~10 s** 建议区间给出告警。

### 3.2 ⚠️ 两处未达标（需决策/补料）

**（1）音色 B 缺素材 —— 本期决定先用单音色跑通。**

零样本合成必须同时提供「一段干净人声」与「这段人声的转写文本」，二者**均无法由程序凭空生成**：前者需真人录音（涉及声音权与合规，见计划书 10.1），后者需人工转写或 ASR（正确率不保证）。因此 D2 的「2 组预置音色」改为：

- 新增 `SPEAKER_A_VOICE` / `SPEAKER_B_VOICE` 说话人映射配置；
- 若 B 音色缺失，按 `SPEAKER_FALLBACK_ENABLED=true` **回退到 A 并显式告警**，而非静默串音：

```
说话人 B 配置的音色 voice_b 不存在，已回退到 voice_a（单音色模式）
```

这一档也顺带解决了一个**真实设计缺陷**：脚本行的 `speaker` 是 `A`/`B`，而音色档案 id 是 `voice_a`/`voice_b`，服务层原本缺少这层映射，直接导致首次 D3 验收以 `VoiceNotFound: 音色不存在：A` 中断。

**（2）现有音色仅 3.48 s，低于建议区间。**

计划书 4.4 节 S6 要求 prompt 素材 **5~10 s**。3.48 s 的 prompt 特征偏少，音色相似度与韵律稳定性都会下降（`make_voice_profile.py` 已对 <5 s 给出告警）。**建议在 D8 逐句试听环节一并替换为主播真人录音。**

| `scripts/make_voice_profile.py` | 音色建档工具 |

| `.gitignore` | **新增**：`.env` 含真实 Key，此前无忽略规则 |

### 4.2 关键设计决策

| # | 决策 | 理由 |
| --- | --- | --- |
| 1 | 缓存键 = `sha1(音色id \| 读文 \| speed \| tone \| 模型版本)` | 与计划书 4.6 `audio_cache.text_hash` 一致。**用「解析后的音色 id」而非脚本 speaker**：同一音色下 A/B 的同名句子应共享缓存，换音色则自然失效 |
| 2 | 缓存目录走**两级散列** `data/cache/{前2位}/{hash}.wav` + 同名 `.json` 元数据 | 单目录堆几万个 wav 会拖慢文件系统；元数据落盘使冷启动无需重新解码音频即可取时长 |
| 3 | `prompt_wav` 传**路径字符串**，绝不传 `load_wav()` 的张量 | `frontend._extract_speech_feat` 内部会再调 `load_wav(path, 24000)`，走 `torchaudio.load`，不接受张量 |
| 4 | **不设** `PYTORCH_CUDA_ALLOC_CONF=expandable_segments` | 实测 Windows 报 `not supported on this platform`，属无效措施（V1.4.0 已剔除）。`load()` 中主动 `os.environ.pop` 掉该变量，避免误导 |
| 5 | 启动期**断言** `frontend.text_frontend != ''`，否则抛 `TextFrontendUnavailable` | **R14 的 fail-fast 防护**。上游对 ttsfrd / wetext 导入失败一律 `except` 兜底 → `text_normalize` 静默退化为原样返回（数字不转写）且不报错，极易漏检到验收 |
| 6 | 切句上限 **40 字**，且切分不得丢字 | 净可用 4.32 GB 下的显存安全档；验收脚本显式校验「读文字符数 == 各分段字符数之和」 |
| 7 | `reversible` 标记**按语义中性区分** | 全半角互转、去 CJK 间空格、空白折叠是语义中性的（标 True）；去 Markdown/emoji/旁白、同音字替换、首尾标点清理是损失性的（标 False 并告警）。混为一谈会让「未命中」告警彻底失去信号价值 |
| 8 | 多音字词典**默认空表** | CosyVoice 的 `wetext` 前端已内置上下文相关的多音字消歧；预填未经验证的整词同音字替换会**主动劣化**音质。该表定位是 D10~D11 的 bad case 修复手段 |

### 4.3 一处被自己否决的设计

`backend/dicts/polyphone.json` 初版曾写入约 200 条「同音字替换」（如 `银行`→`银航`、`应该`→`应改`、`数字`→`数子`）。**这是一处错误设计**：CosyVoice 的 `wetext` g2p 会按词语上下文选读音，而那批条目既未经验证、又与上下文消歧冲突，只会让正常读音变错。已改为默认空表，并在文件内与单测中固化该约定：

```python
def test_shipped_polyphone_dict_is_empty_by_default():
    """内置词典默认必须为空：wetext 已做上下文消歧，预填大词表会主动劣化音质。"""
```

## 六、过程中修复的缺陷

按「发现即修」原则处理，以下为完整清单。

| # | 缺陷 | 影响 | 处置 |
| --- | --- | --- | --- |
| 1 | `normalize.py` 第 4 步残留一行占位代码 `regex_sub(r"[\uff01-\uff5e]", "")`，实际会**删除所有全角标点**（`，`、`！`、`（` 全在 U+FF01–FF5E 区间） | **严重**：句读全丢，且 `２０２６` 全角数字也被删空 | 删除该行（单测 `test_fullwidth_digits_converted` / `test_aside_stripped_but_normal_paren_kept` 捕获） |
| 2 | `%` 未无条件归一化；数字后带空格时「年份」与「量词两」规则双双失效 | `45%` 读成 `四十五%`；`2026 年` 读成 `两千零二十六 年`；规范化不幂等 | ① `%`/`％` 统一为 `％`；② `lookahead` 先 `lstrip`（`test_idempotent` 捕获） |
| 3 | `_read_number` 用**单字符**判量词（`"小".startswith("小时")` 恒为 False） | `2小时` 读成 `二小时` 而非 `两小时` | 改为取后 4 字符做前缀匹配 |

| 5 | 行内标签保护用无索引占位符，还原时丢了方括号 | `[laughter]` 变成 `laughter` | 改为 `哨兵+原文+哨兵`，还原时取回完整 token |
| 6 | `_Doc` 无 `reversible` 属性却被引用 | 所有规范化调用抛 `AttributeError` | 改为按 `edits` 现算 |
| 7 | **说话人映射缺失**：脚本 speaker `A`/`B` 未映射到音色 id `voice_a`/`voice_b` | 首次 D3 验收以 `VoiceNotFound: 音色不存在：A` 中断 | 新增 `SPEAKER_A_VOICE`/`SPEAKER_B_VOICE` 配置与 `_resolve_speaker()`，含显式回退告警 |

| 10 | `smoke_tts.py` 输出文件名用 `hash(text, spk_id)`，且 A/B 共用同一目录 | ① Python `str` hash 每进程随机化、不可复现；② 同文本的 CV2/CV3 产物**互相覆盖**，A/B 结果无法对比 | 改用 `sha1` 前 12 位 + 按模型分目录 |
| 11 | `verify_d3.py` 的 `on_progress` lambda 把条件写在 `append` 内部 | 会插入 `None` 占位 | 改为具名函数 |
| 12 | `verify_d3.py` 报告里 `memory_trace` 存的是**活引用** | 后续 `instruct2` 追加后，`trace` 长度（26）与 `sentences` 计数（25）不一致 | 改为 `list(...)` 浅拷贝 |
| 13 | `make_voice_profile.py` 复制前未创建目标目录 | 首次运行 `FileNotFoundError` | 复制前 `mkdir(parents=True)` |

## 七、被本次实测更正的历史结论

## 十、注意事项

1. **报告 RTF 必须标注冷启动/稳态。** 两者相差约 40%（1.775 vs 1.037），混用会导致容量判断反向。
2. **`prompt_text` 的语义随模型版本变化**，且不匹配时的报错位置具有误导性（表现为声码器异常）。切换 `COSYVOICE_MODEL_DIR` 后**必须先跑一次冒烟**。
3. **`text_frontend` 为空即必须 fail-fast**，不得静默降级——上游会无声跳过数字转写。
4. **音色素材不能由程序生成**，且需注意声音权与合规（计划书 10.1）；请勿使用他人声音未经授权的录音。
5. **多音字词典保持空表**，只在评测发现具体 bad case 时逐条追加。
6. **`.env` 内有真实密钥**，已由 `.gitignore` 覆盖；提交前请确认 `git status` 中不出现 `.env`。
7. **`data/cache/` 不受任务清理策略约束**——它是跨任务共享资产，删除会导致全量重烧。
