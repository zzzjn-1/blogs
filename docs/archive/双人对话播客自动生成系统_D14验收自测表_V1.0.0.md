## 一、使用说明与勾选口径

1. **本表只认可复现的证据。** 每一项都写明「怎么判」与「期望值」；勾选前必须真的跑过或看过对应产物，
   **不接受「应该没问题」**——本项目已多次证明：`assert path.exists()` 这类只查存在性的判据，
   会让真实缺陷活过好几个阶段（`[FIX-FEED-LATEST-01]` 就是这么活过 D6→D12 的）。
2. **三类证据必须在结论旁标明级别**，不得混用：

   | 级别 | 含义 | 例子 |
   | --- | --- | --- |
   | **机器证据** | 脚本可重跑、结果可复算 | `pytest --junitxml` 的三计数、`verify_feed.py`、`verify_demo_pack.py` |
   | **实机证据** | 在真实环境做过的动作与留档 | 断网/杀进程续跑、浏览器截图 |
   | **人证** | 真人听测或人工判断 | MOS「都没问题」、演示录屏 |

   ⚠️ **MOS 只有人证，没有评分表也没有均分。** 本表中凡涉及 MOS 的行，
   只写「真人听测确认达标」，**禁止在答辩材料里改写成「MOS 均分 X」**。
3. **勾选符号**：`[x]` 已自测通过　`[ ]` 未自测/待做　`[~]` 部分达成（必须紧跟说明）。
4. **自测顺序**：先 `A`（起得来）→ `B/C/D`（功能与指标）→ `E`（文档）→ `F/G`（留档与演示物）。
   只要 `A` 不过，后面全部无意义。

## 十、I 组：一次跑完的自动自测命令

```bash
cd /d/podcast-ai
PY=D:/anaconda/envs/cosyvoice/python.exe

# 1) 后端全量回归 —— 只看 junit 三计数，不看控制台（本机汇总行被抑制）
$PY -m pytest -q --basetemp="$TEMP/pytest-podcast-ai-d14" \
    --junitxml=outputs/d14_junit.xml > outputs/d14_pytest.log 2>&1

# 2) 前端门禁（契约 → 类型 → 单测 → 构建）
$PY scripts/check_frontend.py

# 3) 订阅源三方核对 + 判据自证
$PY scripts/verify_feed.py --json outputs/d14_feed_verify.json
$PY scripts/verify_feed.py --self-test

# 4) 演示数据集核验 + 判据自证
$PY scripts/verify_demo_pack.py --json outputs/d14_demo_verify.json
$PY scripts/verify_demo_pack.py --self-test

# 5) 逐句一致率（离线只读）
$PY scripts/verify_consistency.py

# 6) 变异台（必须全红）
$PY scripts/mutation_check_d11.py
$PY scripts/mutation_check_d12.py
$PY scripts/mutation_check_d13.py
$PY scripts/mutation_check_frontend.py

# 7) 文档终检
$PY D:/podcast-ai/scripts/check_spec_docs.py
```

**期望值速查**

| 命令 | 期望 |
| --- | --- |
| pytest + junit | `tests=411 failures=0 errors=0 skipped=0` |
| `check_frontend.py` | 退出码 0 |
| `verify_feed.py` | E- 错误 0 条 |
| `verify_feed.py --self-test` | 4/4 如期变红 |
| `verify_demo_pack.py` | 问题 0 条，演示集 ≥ 3 期 |
| `verify_demo_pack.py --self-test` | 10/10 如期变红 |
| `verify_consistency.py` | 100.00% |
| 四个变异台 | D11 15/15、D12 10/10、D13 3/3、前端 7/7 全红 |
| `check_spec_docs.py` | 现役 22 份全部通过 |

> ⚠️ **两条本机陷阱**（照抄命令即可避开，但换人执行时务必知情）：
> ① **`--basetemp` 每轮必须换一个全新路径**。旧路径残留文件数超过 50 时，pytest 启动清理它会撞「批量删除守卫」
> 抛 `SystemExit`，表现为**大量 `failed on setup` 的假错误**（实测一次 163 个）。
> ② **控制台「一排点全绿」不能当通过证据**——本机 pytest 汇总行被稳定抑制，必须读 junit 的三个计数。
