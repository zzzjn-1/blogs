> 归档日期：2026-09-20

> 对应记录：开发计划书 V1.19.0 版本记录 ④；D11 评测指标达标实施报告 V1.1.0。

## 二、为什么是「移」不是「删」

这 5 个目录是 D4 / D5 / D6 阶段**实测结论的原始证据**（探针 wav、loudnorm 落点、
e2e 构建件、音色换档对照），多份报告逐条引用了里面的文件。删掉它们，
报告里的引用就变成死链，**而且事后无法重建**（重建需要重跑那一轮实验）。
移动保住了引用，只是多一层前缀。

## 三、有意**没有**动的

| 对象 | 原因 |
| --- | --- |
| `data/cache/`（528.81 MB） | 句级缓存是「续跑命中校验」（命中数须严格介于 0 与段数之间）的基础，删了这套验证就不成立 |
| `pretrained_models/`（9.17 GB） | 模型权重，删了系统直接不可用 |
| `outputs/eval/`、`outputs/episodes/`、`outputs/consistency/`、`outputs/d12_crash_recover/`、`outputs/synth_trace/`、`outputs/evidence/` | 现役证据，报告在引用中 |
| **全部被报告引用的日志**（`uvicorn_run.log`、`server3_run.log`、`d11_pytest.log`、`d11_mutation.log` 等） | **日志在本项目里算证据**，不是垃圾 —— D10 报告明确把 `uvicorn_run.log` 当作「阶段标记的唯一来源」 |
| `data/audio/` 与 `outputs/eval/*/audio/` 的内容重复副本 | eval 包与成片库两侧都被引用，删任一侧都会断链 |

## 四、本次一并清理的（可再生成，无回溯价值）

`__pycache__/`、`.pytest_cache/`、`frontend/node_modules/.vite/deps/`、
以及工作区根目录遗留的临时 txt（`_ls_docs.txt` / `_ls_top.txt`）；
合计 **13.71 MB / 5 项**。全部可由工具链自动重建。

## 五、回滚方式

任一项需要回到原位：

```bash
"D:/anaconda/envs/cosyvoice/python.exe" -c "import shutil;shutil.move(r'D:/podcast-ai/outputs/_archive/d5_e2e', r'D:/podcast-ai/outputs/d5_e2e')"
```

移动过程**未改动任何文件内容**（`shutil.move` 同盘移动即改名），因此归档物的字节与归档前完全一致。
