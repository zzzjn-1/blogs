# STORY.md —— 双人对话播客自动生成系统 · D14 答辩 PPT

## ① 用户意图对齐

**目标受众**：校内/实训项目答辩的评审老师（含技术评委与教学评委），15~20 人。
**核心目标**：讲完后希望评委相信三件事——① 这个系统**真的跑通了**（不是 PPT 系统）；
② 它的**指标是可复算的**，不是自我宣称；③ 作者对**自己系统的缺陷有清晰认知**（尤其是踩过的坑。
**PPT 长度**：12 页（精简档）。Hero 配额按「10 页中 2-3 页」的密度折算 → 3 页。
**视觉调性**：学术严谨 / 证据驱动 / 蓝白克制 / 工程实录 / 零营销腔。
**内容边界**：
- **必讲**：一句话产品形态、五段流水线、量化指标与证据级别、两个真实缺陷案例、工程量统计。
- **不讲**：CosyVoice 与 FFmpeg 的 API 细节、SQLAlchemy 会话管理、React 组件树。
- **禁碰**：把 MOS 说成「均分 X」（只有人证、无评分表）；把订阅源离线核对说成「W3C 校验通过」；
  把「一份文档存在」当成「文档合格」。
