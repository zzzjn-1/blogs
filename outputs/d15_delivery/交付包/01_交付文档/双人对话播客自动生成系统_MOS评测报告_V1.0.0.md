## 一、口径纪律（**引用本报告任何结论前必读**）

| # | 规则 | 为什么 |
| --- | --- | --- |
| M1 | **本报告的达标结论是「人证」**：3 位真人听测后反馈「都没问题」，用户据此裁定达标 | 人证能支撑「无重大问题」，**不能支撑任何数值** |
| M2 | **不得写出「MOS 均分 X」「MOS ≈ 4.x」** | **没有这个数**。产出均分的前提是回收到的有效评分表 ≥ 3 份，本轮实测 **0 份** |
| M3 | **`mos_summary.md` 的 `NOT_RECYCLED` 保持原样** | 它不是错误记录，而是脚本对「目录里没有有效评分表」这一事实的**正确输出**。为配合结论去改它，等于把可复现的机器记录污染成人情记录 |
| M4 | **`collect_mos.py` 的判定口径不放宽** | 仍要求 ≥ 3 份有效表才出均分。本次达标是**人工裁量**，走的是与脚本平行的另一条路，不是让脚本「通融」一次 |
| M5 | **bad case 的状态是「听测做过、没提出输入」**，不是「等输入」 | 这两句在验收时极易被当成同一件事，但它们对「系统是否存在 bad case」的判断强度完全不同 |

## 三、回收基建（`scripts/collect_mos.py`）

| 机制 | 说明 |
| --- | --- |
| 输入 | 评测人填好的 `mos_scoresheet_<姓名>.csv`（**必须一人一份**） |
| 判据 | **有效表 ≥ 3 份**才计算均分；不足则**不给出任何数值** |
| 判定码 | `RECYCLED_PASS` / `RECYCLED_FAIL` = **已判定**；`NOT_RECYCLED` = 资料不足、**判不了** |
| 输出 | `mos_summary.json` + `mos_summary.md`（结论码、回收统计、各维度 n/mean/sd/min/max、评分人明细、多音字标记） |
| 写权限 | **只读评分表、只写汇总产物，不回写任何原始评分** |
| 验收线 | 自然度均分 **≥ 3.5**；评测人数 **≥ 3**（开发计划书 §7.2 / R5） |

评分表维度：**自然度（1–5）/ 停顿节奏（1–5）/ 音色区分度（1–5）/ 多音字问题（有/无）/ 备注**。

## 五、真人听评与达标裁定（2026-09-20）

### 5.1 发生了什么

1. 2026-09-18：MOS 包随 `mos_README.md` / `mos_manifest.json` / `mos_scoresheet.csv` 一起发布。
2. 2026-09-20：用户组织 **3 位朋友**实际听该包，反馈结论是**「都没问题」**——未提出任何逐条问题，也未指出具体的多音字 / 停顿 / 响度 case。
3. 用户据此**裁定 MOS 达标**。

### 5.2 取证的边界（写在明面上，不藏在脚注里）

| 维度 | 本次实际 | 计划书要求 | 差距 |
| --- | --- | --- | --- |
| 评测人数 | 3 人 | 3~5 人 | **达标** |
| 是否实际听测 | ✅ 已听 | ✅ | **达标** |
| 结论形态 | 「都没问题」（**定性**） | 自然度均分 ≥ 3.5（**定量**） | **无均分** |
| 书面评分表 | **未回填** | `mos_scoresheet_<姓名>.csv` | **无** |

### 5.3 三个不因「达标」而改变的事实

1. **`mos_summary.md` 里的 `NOT_RECYCLED` 不改**（理由见 M3）。
2. **不补一个均分**。没有评分表就没有均分。「朋友们觉得没问题」是**验收结论**，不是「均分 4.x」。**任何编出来的数值都会成为下游被引用的事实。**
3. **`collect_mos.py` 的口径不放宽**（理由见 M4）。

## 六、升级为机器证据的路径（一步到位）

若日后需要**可量化**的 MOS（论文 / 交付报告里要写数字），按下面做一次，本条人证即升级为机器证据：

```bash
# 1) 评测人各自填好 mos_scoresheet_<姓名>.csv，放回 MOS 包目录
# 2) 一条命令出判定
python scripts/collect_mos.py
# → 退出码 0 表示已判定（RECYCLED_PASS / RECYCLED_FAIL）；2 表示仍判不了
```

届时 `mos_summary.md` 会变成 `RECYCLED_PASS`，**本报告需再升一版**（并把均分写进新版，同时把本条人证标注为「已被机器证据取代」）。

## 七、对 bad case 通道的影响

听测反馈「都没问题」→ **没有产出逐条问题清单** → 开发计划书里「多音字词典按 bad case 清单追加」这条**没有输入**。

**正确表述**：bad case 三项修复手段（多音字词典 / 停顿旋钮 / 响度）**生产链路已接上并有测试**，但**逐条输入通道是空的**；状态为「**听测做过、没提出输入**」。

## 八、结论

| 项 | 结论 |
| --- | --- |
| MOS 是否达标 | **达标**（人证：3 位真人听测确认无问题，用户裁定） |
| 是否可用于量化引用 | ❌ **不可**（无评分表、无均分） |
| 是否已有逐条 bad case 清单 | ❌ 无（听测未提出） |
| 机器侧口径是否已放宽 | ❌ 未放宽，`NOT_RECYCLED` 保持原样 |

**未闭合项**：可量化的 MOS 均分（需回收 ≥3 份有效评分表）。
