## 一、什么是「逐句一致率」

**定义**：对每一行脚本，核验「**合成时实际读的文本**」与「**脚本里写的文本**」是否指向同一条音轨。

弱口径是「文本没被改过」；本项目的判据是**物理口径**——**从落库字段一路核到磁盘上的音频文件**，任何一环对不上都算失败。

---

## 二、判据（行级四层 + 期级两条，**按层短路**）

按层短路的理由：只报**首个未过的层**，避免级联噪音掩盖根因。

| 层 | 判据 | 防的是什么 |
| --- | --- | --- |
| **L1** | `read_text` 非空 | 规范化读文没落库 |
| **L2** | `text_hash` 非空 | 音频指纹没落库 |
| **L3** | `duration_ms > 0` 且 `seg_status = DONE` | 行被当成完成但音轨缺失 |
| **L4** | `text_hash` 能定位到缓存 wav（**文件在盘、时长可解析**） | 台账有、**盘上没有**（被回收 / 改名） |
| **L4b** | 首段时长 ≤ 该行 `duration_ms` + 20 ms | 两个字段指向了不同粒度的音频 |
| **E1**（期级） | 成片音频存在且时长可读 | 成片丢失 |
| **E2**（期级） | Σ行时长 ≤ 成片时长 | 成片 = 片头 + 语音 + 停顿 + 片尾，**必然更长**；反了即数据错 |

## 五、判据踩坑复盘（**本节是本报告最有价值的部分**）

### 5.1 初版判据误报了 14 行

初版把 `text_hash` 当作「**整行**音轨的指纹」，于是 L4 写成**等式**：

```
缓存 wav 实测时长 == 该行 duration_ms
```

首跑结果：

> 已成片 36 期 / 1120 行；一致率 **1106 / 1120 = 98.75%**；失败 14 条 —— 全部是 L4。

**14 条失败无一例外**是「一行多句」的行（如「你一般怎么热？我只会随便哼两句。」），且差值**恒为负**（−1 880 ~ −5 760 ms）。

### 5.2 根因：**两个字段的粒度不同**

落库代码（`task_runner._stage_synthesize`）：

```python
ln.duration_ms = sum(r.duration_ms for r in segs)   # 行级：该行所有段之和
ln.text_hash   = segs[0].text_hash                  # 段级：只有首段
```

一行被切成多段时，`duration_ms` 是**全部段之和**，而 `text_hash` 只指向**首段**。拿段级的缓存 wav 去比行级的时长，**必然对不上**。

### 5.3 正解：换**物理不变量**，而不是放宽容差

- ❌ **错误修法**：把容差从 20 ms 放宽到 6000 ms —— 那等于这条判据什么都不守了。
- ✅ **正确修法**：改用**粒度无关的物理不变量** —— **首段时长 ≤ 整行时长**（+20 ms 数值容差）。多段之和必定不小于首段，这条等式与粒度无关，且仍然能抓住「两个字段指向不同音频」这类真缺陷。

> **判据「差一点点」时，先查口径，不是调阈值。** 这是本项目反复吃到的一条教训。

## 七、结论与偏差声明

**已达成**：逐句一致率 **100.00%**（36 期 / 1120 行全量普查），**机器证据**，可随时离线复跑。

**偏差与例外（必须随结论引用）**

1. **5 个未成片任务（162 行）不计入分母**，全部处于 `PENDING`。它们不是失败样本，而是**没有参与比对的对象**——引用 100% 时须一并说明分母的口径。
2. **一致率 = 100% 不等于「听感完美」**。这条判据守的是「**读的文本与脚本一致**」，它管不了多音字读法是否恰当、停顿是否自然——那两项属于 MOS 与 bad case 的范畴。
3. **初版判据曾误报 14 行（98.75%）**，根因是 `duration_ms`（行级）与 `text_hash`（段级）粒度不同。**该 98.75% 从未成立**，不得作为历史数字引用。
