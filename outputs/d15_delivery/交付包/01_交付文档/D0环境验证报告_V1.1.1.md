## 三、显存专项分析（本报告核心）

### 3.1 计划书 V1.2.1 的预算 vs 实测

计划书 2.5 节对显存的假设与实际存在 **3 倍偏差**：

| 项 | 计划书 V1.2.1 假设 | 实测 | 偏差 |
| --- | --- | --- | --- |
| 显存总量 | 硬上限 6 GB | 6141 MiB（6.00 GB） | ✅ 一致 |
| 桌面 / 驱动占用 | 约 0.5 GB（**未计入合计**） | **1608 MiB（1.57 GB）** | 🔴 **3.1 倍** |
| 留给模型的可用显存 | 目标峰值 5.5 GB | **4313 MiB（4.21 GB）** | 🔴 **少 1.3 GB** |
| 模型侧预算（计划书 2.5 节明细加总） | 4.4 ~ 4.8 GB | — | — |

### 3.2 结论：按现预算必然 OOM

```
模型侧需求    4.4 ~ 4.8 GB
桌面实测占用  +1.57 GB
─────────────────────────
合计需求      5.97 ~ 6.37 GB
显存总量      6.00 GB
─────────────────────────
缺口          −0.37 ~ +0.03 GB   →  超限或零余量
```

即：**最乐观情形下也只剩 0.03 GB 余量，任何一次浏览器硬件加速、视频播放或动态壁纸渲染都可能直接触发 OOM。**

> 说明：WDDM 模式下 CUDA 可向系统内存溢出分页（shared GPU memory），但性能会雪崩式下降，**不可作为兜底手段**。

### 3.3 三条可选路径

| 路径 | 做法 | 预期可用显存 | 风险 |
| --- | --- | --- | --- |
| **A. 腾显存** | ① 关闭 Wallpaper Engine / NVIDIA Overlay / 微信小程序运行时 / Steam-wegame / Edge<br>② 把显示输出切到 AMD 集显（BIOS 或 Windows 显示设置） | 4.21 → **5.2 ~ 5.7 GB** | 需重启，且用户日常使用体验受影响；效果需复测确认 |
| **B. 压模型侧** | int8 量化 + 单句上限 60 → 40 字 + 关闭注意力缓存 | 可压至 ~3.5 GB | 音质与自然度下降，可能影响 MOS ≥ 3.5 指标 |
| **C. 云端 TTS 兜底** | 把云端 TTS 由 P1 兜底升为**主方案** | 显存需求降到近 0 | 需额外云端 API 与费用；任务书指定「CosyVoice 零样本音色合成」，纯云端可能被判未覆盖 |

**建议组合**：先执行 **A**，D0 复测后若可用显存 ≥ 5.3 GB 则按原方案推进；若 < 5.0 GB，则叠加 **B** 的「单句上限降为 40 字」；**C 仅在 A+B 仍不达标时启用**，并在文档中显式声明为「算力约束下的降级策略」。

### 4.3 上游依赖实测要求（已克隆仓库逐行核实）

> **重要修正：当前 main 分支的推理链路已不使用 WeTextProcessing / pynini。**
> 全网大量教程（掘金、CSDN 等）写的 `conda install -c conda-forge pynini==2.1.5 WeTextProcessing==1.0.3` 对应的是**旧版本**；本机实测该命令直接报 `PackagesNotFoundInChannelsError`。**该步骤已无必要，可从计划书 11.2 中删除。**

依据（仓库源码逐行核实）：

| 证据 | 内容 |
| --- | --- |
| `requirements.txt` | 文本正则化依赖为 **`wetext==0.0.4`**（纯 Python，pip 可装），**无** WeTextProcessing |
| `cosyvoice/cli/frontend.py` | 归一化分支仅两个：优先 `ttsfrd`，否则 `wetext`——**不存在 WeTextProcessing 分支** |
| `examples/grpo/cosyvoice2/requirements.txt` | 唯一出现 WeTextProcessing 的位置，属**训练示例**，与推理无关 |
| `docker/Dockerfile` | 仍保留 pynini 安装，属 Linux 训练/容器路径 |

**实测可用安装步骤**：

```bash
git clone --recursive https://github.com/FunAudioLLM/CosyVoice.git
conda create -n cosyvoice -y python=3.10
# 先装 CUDA 版 torch（cu121 与 RTX 4050 / Ada sm_89 匹配）
pip install torch==2.3.1 torchaudio==2.3.1 --index-url https://download.pytorch.org/whl/cu121
# 再装其余依赖（用本项目定制清单 requirements-win.txt）
pip install -r requirements-win.txt -i https://mirrors.aliyun.com/pypi/simple/ --trusted-host=mirrors.aliyun.com
# matcha 为推理必需，从子模块安装
pip install third_party/Matcha-TTS
```

**Windows 定制清单 `D:\podcast-ai\requirements-win.txt` 相对上游的三处改动（均有实测依据）**：

| 改动 | 对象 | 依据 |
| --- | --- | --- |
| 删除 extra-index-url | `aiinfra.pkgs.visualstudio.com` 的 onnxruntime-cuda-12 源 | **实测返回 401 不可达**；且仅 Linux GPU 需要 |
| 删除 `pyworld==0.3.4` | 仅 `cosyvoice/dataset/processor.py`（训练数据）使用 | 推理链路不 import；Windows 无预编译 wheel，需 MSVC 工具链 |
| 删除 `deepspeed` / `tensorrt-cu12*` / `onnxruntime-gpu` | 训练与 Linux GPU 运行时 | 上游已用 `sys_platform == 'linux'` 标记、pip 会自动跳过，显式移除以免干扰 |

**必须保留的依赖（有代码依据，不可删）**：`openai-whisper`（`cosyvoice/tokenizer/tokenizer.py` 依赖）、`onnxruntime`（`cosyvoice/cli/frontend.py` 依赖）。

**`Matcha-TTS` 必须安装**：`cosyvoice/flow/decoder.py`、`cosyvoice/flow/flow_matching.py`、`cosyvoice/hifigan/hifigan.py` 三处 `from matcha...` 导入，缺它 CosyVoice2/3 模型无法初始化。

### 10.1 DeepSeek Key 验证详情（阻塞项）

| 试验 | 请求 | 响应 |
| --- | --- | --- |
| 1 | `GET /v1/models`，Bearer 真实 Key | **HTTP 401** `Authentication Fails, Your api key: ****130c is invalid` |
| 2 | `POST /chat/completions`（JSON 模式，max_tokens=32） | **HTTP 401**，同上 |
| **3（对照实验）** | 同上，但 Bearer 换成 `sk-` + 32 个 `0` | **HTTP 401**，错误文案**与真实 Key 逐字相同**（仅末尾掩码不同：`****0000`） |

**判定**：真实 Key 与全零假 Key 返回完全一致的错误 → **该 Key 在服务端不存在**（已吊销/删除，或复制时缺字符）。排除「请求格式错误」「网络不可达」「余额不足」三种可能（后者的错误码为 402，且响应体为余额提示）。

**处置**：需重新签发 Key。此项**不阻塞 D1 的环境与合成工作**（本地推理链路与该无关），但阻塞 D4 起的脚本生成模块。

### 10.2 网络通道实测结论（决定下载策略）

| 通道 | 小文件 | 大文件 | 结论 |
| --- | --- | --- | --- |
| **ModelScope** | 6~37 KB/s | **19 934 KB/s（19.9 MB/s）** | ✅ **权重唯一可用高速通道**（小文件慢只是 TCP 慢启动） |
| **pypi.org 官方源** | — | **3 548 KB/s** | ✅ 快于国内镜像（aliyun 仅 141 KB/s） |
| download.pytorch.org | 11 KB/s | **726~1 153 KB/s** | ✅ torch wheel 可用（2.4 GB ≈ 40 min） |
| HuggingFace | **HTTP 000 不可达** | 不可达 | ❌ 弃用；`hf-mirror.com` 同样不可用 |
| GitHub（raw/codeload/ghproxy/ghfast） | 3~58 KB/s | 25~58 KB/s | ❌ **git clone --recursive 会断**；必须走 zip + 多镜像 + 断点续传 |
| PyPI（aliyun 镜像） | 141 KB/s | — | 🟠 可用但不优 |

> **教训**：本机小文件测速（5~20 s 采样）会严重低估真实带宽，因为 TCP 慢启动占主导——ModelScope 小文件报 6 KB/s，同一通道的 2 GB 大文件却跑到 19.9 MB/s。**通道评估必须用大文件测**。
