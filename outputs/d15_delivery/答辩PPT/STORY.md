# STORY.md —— 双人对话播客自动生成系统 · 答辩 PPT（17 页）

## ① 用户意图对齐

**目标受众**：嘉应学院数学学院答辩评审（技术评委 + 教学评委），现场十几人。
**核心目标**：讲完希望评委信三件事——① 这东西**真的跑通了**（不是 PPT 系统）；② 指标**可以现场复算**，不是自我宣称；③ 我对**自己的缺陷有清晰认知**，连没做完的也照实说。
**PPT 长度**：17 页（现场讲 13~15 分钟）。Hero 配额按「10 页中 2-3 页」折算 → 3 页。
**视觉调性**：白纸黑字 / 工程实录 / 零营销腔 / 口语化 / 有手写笔记感而不是模板感。
**演讲备注**：**每页都写**，第一人称口语稿（用户明确要求）。
**内容边界**：
- **必讲**：一句话产品形态、四个输入参数、五段流水线、14 天四阶段、三项硬指标（含口径）、六个真实缺陷、没做完的事。
- **不讲**：CosyVoice / FFmpeg 的 API 细节、SQLAlchemy 会话管理、React 组件树、训练原理。
- **禁碰**：把 MOS 说成「均分 X」（只有人证、无评分表）；把离线跨产物核对说成「W3C 校验通过」；把「文档存在」当成「文档合格」；把 8.1~8.9 min 当现有结论（那是**冷启推算**，已被 5.4~6.2 min 取代）。
